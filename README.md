# L01 — Simple SDL

**Video Game Development (804237 DESVJ) · CITM UPC**

The starting point of the course: a minimal SDL3 application with no engine
around it. One file, one window, one moving square.

Use this branch to check that your toolchain works before we add any structure.

## What is here

| File | Purpose |
|---|---|
| `PlatformGame.cpp` | The whole program: init, window, renderer, main loop, cleanup |
| `vcpkg.json` | Declares the SDL3 dependency (manifest mode) |
| `PlatformGame.sln` / `.vcxproj` | Visual Studio 2022 solution and project |

## Build

1. Open `PlatformGame.sln` in Visual Studio 2022.
2. Select the **x64** platform.
3. Build. The first build downloads and compiles SDL3 through vcpkg and will
   take several minutes — this is normal and only happens once per machine.
4. Run. A window opens with a blue square you can move with the arrow keys.

If vcpkg does not run, open a terminal in Visual Studio (*View → Terminal*) and
run `vcpkg integrate install`, then reopen the solution.

`vcpkg_installed/` is generated by the build and is not committed. It is
recreated whenever you clone the project on a new machine.

## What to read in the code

`PlatformGame.cpp` is deliberately flat so the shape of every SDL program is
visible in one screen:

1. `SDL_Init` — start the subsystems
2. `SDL_CreateWindow` / `SDL_CreateRenderer` — get something to draw on
3. **the main loop** — poll events, update state, render, repeat
4. `SDL_Destroy*` / `SDL_Quit` — give the resources back

Everything we build for the rest of the course is structure placed around that
loop. It never goes away.

## Try it

- Start the square at a different position.
- Change its colour.
- Add a second square that moves independently.

Then move on to `L01_Simple_Engine`, where the same program is reorganised into
modules.
